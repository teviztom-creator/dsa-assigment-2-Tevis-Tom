Performance vs Load Factor:
- Linear: Expected unsuccessful search ≈ 0.5*(1 + 1/(1-α)^2)
  At α=0.7 => ~6 probes. Suffers PRIMARY CLUSTERING.
- Quadratic: Better, avoids primary clustering, but SECONDARY CLUSTERING.
  Needs prime table size & α < 0.5 for guarantee.
- Double Hashing: Expected ≈ 1/(1-α) ≈ 3.33 at α=0.7, best distribution.
  Probe sequence depends on key, so no clustering.

Comparison Result:
- Linear: Simplest, cache-friendly, but 1+2+3+4+5+6+7 = 28 probes total for this dataset.
- Quadratic: Needs prime m. Better distribution, but may fail if m non-prime.
- Double Hashing: Most uniform, least probes (avg ~1.5-2.0), best for heavy collision.

MOST SUITABLE: DOUBLE HASHING for this railway booking case where IDs collide heavily.
If implementation simplicity is priority and table kept <50% full, Linear is okay.
